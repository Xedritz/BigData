✅ Ventajas reales

Aprovechar
  • Vives en Colombia: costo de vida bajo, USD remoto = arbitraje brutal.
  • MacBook Air M4: hardware sobrado para todo lo no-GPU; lo demás se hace en cloud.
  • Te gusta el stack correcto (Python, SQL, Linux, cloud, APIs). Eso es 80% del trabajo real.
  • No tienes deuda académica ni inercia de carrera previa: puedes especializarte rápido.

⚠️ Riesgos a neutralizar

Atacar ya
  • Inglés. Bloqueador #1 para Big Tech. Sin C1 conversacional, te tope quedas en LATAM.
  • No tener título te cuesta cero en startups de USA/EU y mucho en empresas tradicionales. Elige bien.
  • Tentación de saltar a “AI Engineer” sin fundamentos: morirás en la primera entrevista técnica.
  • Tutoriales infinitos sin construir: el mercado paga por portafolio y experiencia, no por horas viendo videos.

🎯 Apuestas estratégicas

Decidir
  • Especialización en Data Engineering moderno (dbt + Spark + Cloud) como columna vertebral.
  • Cloud principal: AWS primero (mayor mercado), GCP después si vas a ML/AI.
  • Capa AI/ML encima de DE: AI Engineering con LLMs/RAG es el área de mayor crecimiento 2025-2028.
  • Construir en público: GitHub + LinkedIn + 1 blog/portfolio. Tu currículum es tu repositorio.

🔥 Verdades incómodas (léelas dos veces)

1. Nadie te va a contratar como “Data Engineer Senior” en 6 meses. Si alguien te lo promete, te está vendiendo humo. Camino realista a DE empleable: 12–18 meses sólidos.
2. Certificaciones no reemplazan portafolio. Una sola certificación + 3 proyectos sólidos pesa más que 5 certificaciones sin código.
3. Tu inglés determinará tu techo salarial más que cualquier stack técnico. Habla en inglés desde el día 1, aunque te dé vergüenza.
4. “AI Engineer” sin fundamentos de Data Engineering es un castillo de naipes. Los modelos no sirven si tus datos están rotos.
5. LeetCode no te hace Data Engineer, pero sí es la única forma de pasar entrevistas Big Tech. Acepta el juego.
6. La consistencia diaria de 3–4h disciplinadas, vence a 10h fines de semana. Compounding is the only superpower.

📚 Recursos del Árbol de Dependencias

Cada nivel del roadmap tiene aquí 2–3 recursos curados — los mejores que existen para esa habilidad. Prioridad: gratis. Solo aparecen recursos premium cuando son brutalmente superiores. Marca cada uno cuando lo completes.

Cómo leer los recursos: 📺 = curso/video · 📖 = libro · 📄 = docs oficiales · 🎮 = interactivo/práctica · 🎙 = podcast · 🛠 = proyecto/práctica guiada. FREE = gratis · PAID = de pago (vale la pena) · ELITE = top mundial en su categoría.
🌱 Nivel 0 · Fundamentos Universales

🐧 Linux / Bash / Terminal

  • 📺 The Missing Semester of Your CS Education — FREE ELITE · MIT · 11 clases (~15h). Lo que la universidad no te enseña: terminal, vim, bash, git, dotfiles. Empieza por aquí, punto.
  • 📖 The Linux Command Line (William Shotts) — FREE · ~550 pp. PDF gratis. El libro canónico de Linux para mortales. Léelo en paralelo a Missing Semester.
  • 🎮 OverTheWire: Bandit — FREE · 34 niveles CTF. Aprendes bash haciendo, no leyendo. Una hora al día durante 2 semanas y dominas la terminal.

⎇ Git & GitHub

  • 📖 Pro Git (Scott Chacon) — FREE · Libro oficial de Git, lectura completa en ~2 semanas. Capítulos 1–3 son suficientes para empezar.
  • 🎮 Learn Git Branching — FREE · Tutorial visual interactivo. Entiendes branches/merges/rebase en 2h jugando.
  • 📺 GitHub Skills — FREE · Cursos oficiales hands-on: pull requests, code review, GitHub Actions. ~30 min cada uno.

🌐 Inglés técnico (B2 → C1)

  • 🎙 BBC Learning English — FREE · Podcasts diarios "6 Minute English". Input pasivo mientras cocinas o caminas.
  • 📺 iTalki — PAID ($5–15/clase) ELITE · Profesor nativo 2–3 veces por semana. Lo ÚNICO que mueve la aguja en speaking. Vale cada dólar.
  • 📺 Cambridge English (YouTube) + Anki con deck "English Vocab for Programmers" — FREE · Vocabulario técnico vía espaciado.

🧠 Pensamiento computacional

  • 📺 CS50x (Harvard, edX) — FREE ELITE · 11 semanas. El curso introductorio más respetado del mundo. C → Python → SQL. David Malan es referente mundial.
  • 📖 How to Design Programs — FREE · Libro online sobre cómo PIENSAN los buenos programadores. Más profundo que CS50.
💻 Nivel 1 · Lenguajes Núcleo

◇ SQL (básico → ventanas, CTEs, optimización)

  • 🎮 SQLBolt — FREE · 18 lecciones interactivas, de SELECT a joins. 4–6h. Empieza aquí.
  • 📺 Mode SQL Tutorial — FREE ELITE · El mejor tutorial gratis para SQL intermedio-avanzado: CTEs, window functions, performance. ~20h.
  • 🎮 DataLemur / StrataScratch — PAID ($20–30/mes) · Problemas reales de entrevistas FAANG. Tier 1 para prepararte para entrevistas. Free tier disponible.

🐍 Python (básico → OOP → APIs → async → testing)

  • 📖 Python Crash Course 3rd ed (Eric Matthes) — PAID (~$30 físico, ejercicios free online) ELITE · El mejor primer libro de Python. Hands-on desde la página 1.

Etapa 1 · ETL vs ELT — entender bien el cambio (semana 1)

ETL (clásico): Extract → Transform → Load. Transformación fuera del warehouse. Usado con on-prem y warehouses caros.

ELT (moderno): Extract → Load → Transform. Cargas crudo al warehouse/lakehouse y transformas con SQL/dbt allí. Esto es el estándar 2020+.

📌 Hoy "Data Engineer moderno" hace principalmente ELT con dbt + warehouse, no ETL clásico con Informatica/SSIS.

  • TaskFlow API (decoradores @task) — el nuevo estándar.
  • Variables, Connections, XComs.
  • Sensors (poke vs reschedule), TriggerRules.
  • Backfills, catchup, max_active_runs.
  • Custom operators, hooks, plugins.
  • Deployment con Astronomer o MWAA (AWS).
  • Alternativas modernas: Dagster (asset-based, mejor DX) y Prefect (más Pythonic). Aprende Airflow primero porque es el del mercado.

  • Materialization: view, table, incremental, ephemeral.

  • Patrones: insertonly, merge, snapshot.

Etapa 4 · Spark (PySpark) profundo (6 semanas)
  • Arquitectura: driver, executors, cluster manager (YARN, K8s, standalone).
  • DataFrames API, lazy evaluation, Catalyst optimizer.
  • Lectura/escritura: Parquet, ORC, Delta, Iceberg, JDBC.
  • Particionado físico (write) vs lógico (compute).
  • Shuffle: cuándo ocurre, cómo evitarlo, broadcast joins.
  • Skew handling: salting, AQE skew join optimization.
  • Spark UI: leer DAG, stages, tasks.
  • Tuning: spark.sql.shuffle.partitions, executor memory, cores, off-heap.
  • UDFs vs Pandas UDFs (Arrow) — preferir built-ins siempre.
  • Spark Structured Streaming: micro-batch, triggers, watermarks, state.
⚠️ El 80% de problemas de Spark en prod son por particionado mal pensado y shuffles innecesarios. Domina eso antes que técnicas avanzadas.
Etapa 5 · Kafka y streaming (4 semanas)
  • Conceptos: topics, partitions, offsets, consumer groups, brokers.
  • Producer/Consumer en Python (confluent-kafka).
  • Schema Registry + Avro/Protobuf.
  • Kafka Connect (source/sink connectors).
  • Delivery semantics: at-most-once, at-least-once, exactly-once.
  • Streaming patterns: CDC con Debezium, event sourcing, CQRS.
  • Alternativas: Redpanda (Kafka-compatible, más rápido), Pulsar.
Etapa 6 · Data Lakes, Lakehouse y Medallion
  • Data Lake clásico: S3 + Parquet + Hive Metastore. Problemas: no ACID, schema evolution dolorosa.
  • Lakehouse: Lake + ACID + schema evolution + time travel. Es el estándar 2024+.
  • Delta Lake (Databricks-origin, OSS): el más maduro, mejor en Spark.
  • Apache Iceberg (Netflix-origin): el ganador del estándar industria 2024-2025. AWS, Snowflake, BigQuery lo soportan.
  • Apache Hudi: Uber-origin, fuerte en upserts/CDC.
  • Medallion Architecture: Bronze (raw) → Silver (cleaned) → Gold (business-ready). El patrón de oro para lakehouse.
📌 2026 prediction: Iceberg será el estándar dominante. Prioriza aprenderlo, sin abandonar Delta.

  • Data contracts: definir schema y SLA entre productores y consumidores.
  • Lineage: OpenLineage como estándar emergente; Marquez como UI.

∞ Big Data & Sistemas Distribuidos

"Big Data" no es buzzword, es una clase de problemas: cuando los datos no caben en una sola máquina y necesitas paralelismo + tolerancia a fallos. Si entiendes los principios, las herramientas son intercambiables.

🧠 Fundamentos teóricos (no opcional para Sr+)

Conceptos que debes saber explicar

  • Teorema CAP: Consistencia, Disponibilidad, Tolerancia a particiones — solo 2.
  • BASE vs ACID: trade-offs entre disponibilidad y consistencia.
  • Consensus: Paxos, Raft (a nivel conceptual).
  • Replication: leader-follower, multi-leader, leaderless.
  • Sharding / partitioning: hash, range, lookup.
  • Eventual consistency, causal consistency, linearizability.
  • Idempotencia y exactly-once semantics.
  • Backpressure en sistemas streaming.
📚 Lectura obligatoria: "Designing Data-Intensive Applications" de Martin Kleppmann. El único libro de sistemas distribuidos que no es académico inútil.

MapReduce → Spark → Lakehouse · evolución

  • 2004-2014: MapReduce (Hadoop) — escribir a disco entre stages.
  • 2014-2020: Spark — in-memory, lazy, mejor API.
  • 2017+: Flink — streaming-first con semánticas exactly-once nativas.
  • 2019+: Delta/Iceberg/Hudi — ACID sobre object storage.
  • 2022+: Photon, DuckDB, Velox — vectorización a nivel CPU SIMD.
  • 2024+: Lakehouse unifica batch+stream+ML sobre Iceberg.
Spark profundo · Catalyst, planning, tuning

Catalyst optimizer: entiende cómo Spark transforma tu query en un plan físico. Lee EXPLAIN EXTENDED de tus queries.

Adaptive Query Execution (AQE): ajusta el plan en runtime. Activado por defecto en 3.x. Skew join optimization y dynamic partition pruning son tus amigos.

Particionado físico vs in-memory: aprenderás esto fallando. Particiona por columna de filtro frecuente, no por la del join.

Shuffle dolor: reduce spark.sql.shuffle.partitions de 200 default a algo razonable para tu volumen. Broadcast joins para tablas pequeñas (<100MB).

Memory tuning: executor.memory, executor.memoryOverhead, off-heap. Errores OOM en executors suelen ser por colocar datos demasiado grandes en variables Python.

Kafka · arquitectura y patrones
  • Replication factor (típico 3), min ISR, acks (0, 1, all).
  • Particiones determinan paralelismo máximo de consumo.
  • Consumer groups, rebalance, cooperative sticky.
  • Compactación de topics (changelog pattern).
  • Kafka Connect: source/sink connectors sin código.
  • KSQL/ksqlDB para SQL sobre streams (revisar, no esencial).
  • Kafka Streams (JVM) — alternativa a Flink para casos simples.
Flink · streaming verdadero

Flink es el real deal de streaming: exactly-once nativo, event-time vs processing-time, watermarks, state management profundo. Aprende los conceptos incluso si en tu trabajo usan Spark Streaming.

  • DataStream API vs Table API.
  • Windowing: tumbling, sliding, session, global.
  • State backends (memory, RocksDB), checkpointing.
  • Late events handling, allowed lateness.
  • Flink SQL — productividad seria.
Escalabilidad y tolerancia a fallos
  • Scaling vertical vs horizontal: límites prácticos del vertical.
  • Stateless vs stateful: los servicios stateless escalan trivialmente.
  • Idempotencia: diseña operaciones que se puedan reintentar sin daño.
  • Dead-letter queues para eventos malos.
  • Circuit breakers, retries con backoff exponencial.
  • Chaos engineering básico — fail intentionally para encontrar bugs.

✦ AI & Machine Learning

El campo se dividió: ML clásico (sklearn, predicciones tabulares) sigue importando para la mayoría de negocios, y AI moderno (LLMs, RAG, agents) es la frontera caliente. Necesitas ambos a nivel funcional.

📐 Matemáticas necesarias (la dosis correcta)

📌 Verdad incómoda: NO necesitas un máster en matemáticas para ser ML/AI Engineer. Necesitas: álgebra lineal a nivel "entiendo vectores, matrices, eigenvalores", cálculo a nivel "entiendo gradientes y backprop conceptualmente", y estadística aplicada (distribuciones, hipótesis, regresión).
  • Álgebra lineal: 3Blue1Brown "Essence of Linear Algebra" (YouTube) + ejercicios prácticos.
  • Cálculo: 3Blue1Brown "Essence of Calculus" + derivadas parciales y chain rule.
  • Probabilidad y estadística: Bayes, distribuciones, intervalos de confianza, A/B testing.
  • Optimización: gradiente descendiente y variantes a nivel intuitivo.
Camino 1 · ML Fundamentals (3–4 meses)

📚 Lo que debes dominar para Big Tech

Algoritmos y Estructuras de Datos

  • Arrays, strings, hash maps, linked lists, stacks, queues, heaps, trees, tries, graphs.
  • Algoritmos: sorting, BFS/DFS, dynamic programming, greedy, two pointers, sliding window.
  • Big-O analysis en cada problema.
  • Meta de LeetCode: 250-400 problemas (mezcla easy/medium/hard 30/50/20).
  • Patrones > problemas individuales: aprende los 20-25 patrones canónicos.

System Design

  • Trade-offs: consistency vs availability, latency vs throughput, cost vs perf.
  • Componentes: load balancers, caches, CDNs, queues, DBs (SQL/NoSQL), object storage, search.
  • Casos canónicos: URL shortener, Twitter feed, rate limiter, chat system, recommendation system.
  • Para Data Eng: diseña un data lake/warehouse, sistema de ingest a 1M events/s, lineage tracker.
  • Para ML Eng: diseña sistema de recomendación a escala, feature store, real-time inference.
